# Волонтёры Беларуси

Единый координационный центр волонтёрской помощи по 4 направлениям:

- 🐾 Приюты для животных
- 🤝 Помощь пожилым
- 🧭 Поиск пропавших (ПСО)
- 🌳 Благоустройство городов

Стек: **Next.js 16** (App Router, TypeScript, Tailwind CSS 4) · **PostgreSQL** (Neon, serverless) · **Prisma 7** · **Auth.js v5** (email/пароль). Хостинг — Vercel (бесплатный план).

## Возможности

- Каталог заявок с фильтрацией по направлению, городу и тексту
- Авторизация и три роли: **волонтёр**, **организатор**, **администратор**
- Личный кабинет волонтёра: профиль, навыки, интересы, отклики, часы помощи
- Кабинет организатора: верификация, размещение заявок, работа с откликами (одобрить/отклонить/отметить выполненной), учёт часов
- Админка: статистика, верификация организаций, управление статусами заявок, новости
- Новости с админ-публикацией
- Демо-данные через seed

## Запуск локально

1. Установите зависимости:

   ```bash
   npm install
   ```

2. Создайте базу данных **Neon** (бесплатно, PostgreSQL 16+). Выдайте строку подключения и положите её в `.env`:

   ```env
   DATABASE_URL="postgresql://USER:PASSWORD@ep-xxx.region.aws.neon.tech/neondb?sslmode=require"
   AUTH_SECRET="сгенерируйте любое длинное значение"
   AUTH_TRUST_HOST="true"
   ```

   Генерация `AUTH_SECRET`: `openssl rand -base64 32` или просто случайный текст.

   Файл `.env` скопируйте из `.env.example`.

3. Примените схему БД и заполните демо-данными:

   ```bash
   npx prisma migrate dev --name init
   ALLOW_DEMO_SEED=true npx prisma db seed
   ```

4. Запустите:

   ```bash
   npm run dev
   ```

   Откройте http://localhost:3000

## Деплой на Vercel

1. Создайте **GitHub-репозиторий** и запушьте проект (`.env` уже в `.gitignore`).
2. На https://vercel.com нажмите **Add New → Project**, выберите репозиторий.
3. В настройках проекта укажите переменные окружения (те же, что в `.env`): `DATABASE_URL`, `AUTH_SECRET`, `AUTH_TRUST_HOST="true"`, а для проверки почты — SMTP: `SMTP_HOST`, `SMTP_PORT`, `SMTP_SECURE`, `SMTP_USER`, `SMTP_PASS`, `MAIL_FROM_EMAIL`, `MAIL_FROM_NAME` (см. `.env.example`; можно обойтись бесплатным ящиком Yandex/Gmail с паролем приложения, либо альтернативно `BREVO_API_KEY`).
4. Нажмите **Deploy**. Vercel сам выполнит миграции? **Нет** — их нужно применить вручную (см. ниже).

### Применение миграций на прод-БД

Перед запуском новой версии из локальной машины выполните (с рабочим `DATABASE_URL` в `.env`):

```bash
npx prisma migrate deploy
```

Миграции применяются к PostgreSQL перед запуском новой версии. Не запускайте демо-seed на рабочей базе: он создаёт аккаунты с известным паролем.

Первого администратора создайте через обычную регистрацию с индивидуальным паролем и подтверждением почты, затем назначьте роль ADMIN вручную в БД только проверенному аккаунту. Публичного выбора роли администратора нет. Если демо-аккаунты уже существуют на рабочей базе, удалите или смените их учётные данные и отзовите сессии.

Миграция `20260908200000_coordination_integrity` добавляет отмену участия, лимиты запросов и пересчитывает места и часы по существующим откликам. Перед применением сделайте резервную копию. Старые события с датой без времени не переводятся автоматически: организатор должен указать верное время по Минску.

## Структура проекта

```
prisma/
  schema.prisma        # модели и энумы
  seed.ts              # демо-данные
src/
  app/                 # маршруты (App Router)
    (auth)/            # логин и регистрация
    zayavki/           # каталог заявок и детальная страница
    volunteer/         # кабинет волонтёра
    organizer/         # кабинет организатора (в т.ч. /create, управление откликами)
    admin/             # админка (верификация, новости)
    novosti/ napravleniya/ about/ kak-eto-rabotaet/ kontakty/   # инфо-страницы
  lib/
    db.ts              # Prisma-клиент с драйвером pg
    auth.ts            # Auth.js v5
    guards.ts actions/ # гварды ролей и server actions
  components/          # UI и клиентские формы
  generated/prisma     # сгенерированный Prisma Client (в .gitignore)
```

## Проверки и правила участия

- `npm test` проверяет даты независимо от часового пояса процесса и права доступа к изменениям профилей.
- `TEST_DATABASE_URL=postgresql://... npm run test:integration` проверяет сценарии на отдельной PostgreSQL-БД. Имя БД должно оканчиваться на `_test`; тесты очищают только эту тестовую БД. Сначала примените миграции к ней.
- PENDING и APPROVED резервируют место. Одобрение существующего отклика не занимает второе место. Повторный отклик после отмены пока недоступен.
- Отменить участие можно до начала события, а после переноса — также до ответа на новую дату. WITHDRAWN не влияет на надёжность. Завершённые статусы не меняются произвольным запросом.
- Новые события вводятся по времени Минска; часы встречи отображаются одинаково в любом часовом поясе браузера и сервера.
- Контакты видны владельцу заявки и участникам со статусами APPROVED, DONE или NO_SHOW. Город и телефон профиля волонтёра обязательны для отклика.
- При удалении аккаунта история удаляется каскадно, а места и часы оставшихся пользователей пересчитываются. Это не архивирование истории помощи.
- `CRON_SECRET` защищает `/api/cron/attendance`. Задание в `vercel.json` запускается ежедневно в 07:00 UTC (10:00 Минск) в production. Оно создаёт внутренние напоминания и нейтрально отменяет неподтверждённые участия после новой даты. До обработки задания выставить неявку таким участникам всё равно нельзя. Повторный запуск не дублирует уведомления. На preview вызывайте endpoint вручную с Bearer-секретом.
- Уведомления доступны в `/uvedomleniya`; счётчик учитывает всю непрочитанную историю. Email используется для подтверждения регистрации; рассылка событий по email пока не подключена.
